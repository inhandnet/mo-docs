Mo OS uses Debian on Arm64. Software availability, kernel features and accelerator support still need to be checked for the board and image in use. These entries distinguish documented tests from possible future integrations; inclusion does not imply partner certification or official support by another project.

## Documented Mo62A paths

| Software | What was checked | Guide |
|---|---|---|
| Docker / Compose | The commands and kernel-dependent limits described in the guide | [Containers](../mo-62a/application-deployment/containers.mdx) |
| Node-RED | Installation and a local flow on the documented image | [Partner applications](../mo-62a/application-deployment/partner-applications.mdx) |
| TI TIDL / ONNX Runtime | Selected model compilation and Python/C++ inference paths; compatibility is model-specific | [AI development](../mo-62a/application-development/ai/index.mdx) |
| TI MCU+ SDK / FreeRTOS | MCU R5F echo and console examples with documented reload limits | [Real-time cores](../mo-62a/real-time-cores/index.mdx) |

## Integration candidates

Armbian images, Ultralytics model workflows, Frigate, Torizon, Zephyr, ROS 2 / micro-ROS, Edge Impulse, Viam and Mender are candidates for separate evaluation. These guides do not establish their board support, NPU integration, real-time behavior or production readiness. In particular, a container starting successfully does not prove that its detector uses TIDL.

For a concrete integration request, [contact InHand](/contact) with the board, image, upstream version and required behavior.
