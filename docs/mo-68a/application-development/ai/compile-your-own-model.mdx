Compilation turns an ONNX, TFLite or TVM model into TIDL artifacts that the C7x
and MMA can execute. It runs on the x86 PC set up in
[Toolchain](./toolchain.mdx), never on the board.

## Compile the reference models first

Run the bundled models before your own. It proves the toolchain end to end, and
it gives you a working example to compare against when your own model behaves
oddly.

With the environment restored:

```bash
cd ~/edgeai-tidl-tools
source venv/bin/activate
source ./setup_env.sh am68a

mkdir -p build && cd build
cmake ../examples && make -j2 && cd ..

source ./scripts/run_python_examples.sh -o
python3 ./scripts/gen_test_report.py
```

`-o` means compile only. The script downloads about 200 MB of source models into
`models/public/` and compiles them into about 720 MB of artifacts — eight models
across both runtimes:

| ONNX | TFLite |
|---|---|
| `resnet18_opset9.onnx` | `mobilenet_v1_1.0_224.tflite` |
| `mobilenetv2-1.0.onnx` | `ssd_mobilenet_v2_300_float.tflite` |
| `ssd-lite_mobilenetv2_fpn.onnx` | `ssdlite_mobiledet_dsp_320x320_coco.tflite` |
| `deeplabv3lite_mobilenetv2.onnx` | `deeplabv3_mnv2_ade20k_float.tflite` |

`gen_test_report.py` then runs inference on the PC and writes a per-model
pass/fail summary:

```bash
cat test_report_pc_am68a.csv | column -t -s,
```

## What compilation produces

| Path | Contents |
|---|---|
| `models/` | The source models |
| `model-artifacts/` | Compiled TIDL artifacts, one directory per model |
| `output_images/` | Annotated images from the PC inference run |
| `test_report_pc_am68a.csv` | Per-model pass/fail summary |

`models/` and `model-artifacts/` are the two directories the board needs.

## Move the artifacts to the board

The board needs its own checkout of the tools — the image carries the runtime
libraries, not the repository:

```bash
cd /opt
git clone https://github.com/TexasInstruments/edgeai-tidl-tools.git
cd edgeai-tidl-tools
git checkout <TIDL_TAG>
```

Then, from the PC, stream both directories across:

```bash
cd ~/edgeai-tidl-tools
tar -czf - model-artifacts/ models/ \
  | ssh <user>@<board-ip> "cd /opt/edgeai-tidl-tools && tar -xzf -"
```

[First NPU demo](../../getting-started/first-npu-demo.mdx) runs them on the
board.

## Your own model

The same two steps apply to a model of your own: compile it on the PC against
the tag your board reports, then copy `model-artifacts/` across. Two things
decide whether the result is useful.

**Operator coverage.** TIDL offloads the subgraphs it supports and leaves the
rest on the Cortex-A72. A model that compiles is not necessarily a model that is
accelerated — read the compiler's operator report to see what was taken.

**Calibration data.** Compilation quantizes the model, using sample inputs to
set the ranges. Inputs that do not represent what the model will actually see
produce a model that runs fast and predicts badly. Keep the calibration set
separate from the set you evaluate accuracy against.
