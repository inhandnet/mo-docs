## Connect the debug UART

Use a 3.3 V USB-to-TTL adapter on J4, the three-pin SH1.0 debug connector. This is not the 40-pin header UART5. Shut down and disconnect board power before wiring; locate the connector and physical pin 1 on the actual board.

| J4 pin | Board signal | USB-UART adapter connection |
|---|---|---|
| 1 | UART0 RX | Adapter TX |
| 2 | GND | Adapter GND |
| 3 | UART0 TX | Adapter RX |

Leave the adapter's power wire disconnected and power Mo62A through its normal supply. Do not use an RS-232-level interface or a 5 V signal output. Wire colours are not a pinout.

The J4 circuit is on the right-hand side of the [original schematic sheet 17](../hardware-development/schematics.mdx#connector-circuits-sheet-17); the [connector table](../hardware-development/hardware-interfaces.mdx#connector-map) gives its board position.

## Open a host terminal

Select the adapter's actual device, preferably its stable `/dev/serial/by-id/` path when available. The example `/dev/ttyUSB0` is not guaranteed on every host.

```bash
ls -l /dev/serial/by-id/
minicom -s
```

In **Serial port setup**, select the device and set 115200 baud, 8 data bits, no parity, 1 stop bit, and both hardware and software flow control off. Save the configuration, then open the terminal, for example:

```bash
minicom -D /dev/ttyUSB0 -b 115200
```

The command selects a device and baud rate; confirm the other settings in minicom rather than assuming a previous profile is correct. On hosts that restrict serial devices, use the appropriate group membership and re-login; do not make the device world-writable.

Open the terminal before powering on to capture the boot sequence. Avoid typing while collecting an uninterrupted boot log. The current source has changed autoboot/menu behaviour, so do not assume an older interactive menu or countdown is present. For normal overlay selection from a running system, use [Device tree overlays](../system-configuration/device-tree-overlays.mdx).

## Confirm Linux console state

From an existing local or SSH session, the following checks do not consume serial input or change its settings:

```bash
tr ' ' '\n' < /proc/cmdline | grep '^console='
systemctl is-active serial-getty@ttyS2.service
```

## Troubleshooting and log sharing

| Symptom | Check |
|---|---|
| No output at all | Correct host adapter, common ground, crossed TX/RX, J4 pin numbering and board supply |
| Garbled characters | 115200 8N1, 3.3 V signalling, stable power and cable quality |
| Output appears but input does not work | Adapter TX to board RX, flow control disabled and no competing serial application |
| Linux boots but no login prompt | Confirm the `ttyS2` console argument and `serial-getty@ttyS2.service` state |
| Host permission denied | Adapter-device ownership and group access; re-login after group changes |

Keep raw logs private until reviewed. Remove account names if needed, passwords, tokens, network identifiers and confidential application output before attaching a log to a public issue. Never record a password-entry session for documentation.
