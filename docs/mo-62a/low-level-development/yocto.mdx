## Current support boundary

The documented Mo OS image is Debian-based. No validated Mo62A-specific Yocto layer set, BitBake machine configuration, build manifest and boot-tested image were established in this review. Do not treat the SDK's `YOCTO_MACHINE=am62axx-evm` setting as a complete Mo62A Yocto BSP.

The [software and resource capture](../mo-os/using-mo-os.mdx#identify-the-software-and-resources) in Using Mo OS shows the Debian-based environment that this site documents.

## Why Yocto names appear in the SDK

The TI SDK includes OpenEmbedded/Arago-derived toolchains, sysroots, manifests and firmware. Its `Rules.make` retains `am62axx-evm` as a platform-related build variable, while the U-Boot board defconfigs are Mo62A-specific. The [SDK target inspection](./build-from-source.mdx#build-and-stage-the-actual-targets) in Build from source shows both settings; it is a source inspection, not a BitBake build result.

TI's [Processor SDK 11.01.07.05 Yocto build guide](https://software-dl.ti.com/processor-sdk-linux/esd/AM62AX/11_01_07_05/exports/docs/linux/Overview_Building_the_SDK.html) describes its upstream layer setup and `am62axx-evm` image build. That target is the TI platform reference, not a demonstrated drop-in image for Mo62A.

## Work needed for a Mo62A port

| Area | Mo62A-specific work to verify |
|---|---|
| Layer and revision manifest | Pin all layers, patches, licenses and source revisions |
| Machine definition | DRAM options, boot medium, device trees, bootloader variants and image layout |
| Kernel / U-Boot | Carry the actual board configuration, overlays and interface fixes |
| Firmware / AI userspace | Match C7x/R5 firmware, TIDL libraries, runtimes and model artifacts |
| Image contents | Drivers, network, desktop or headless services, users and update policy |
| Production workflow | Reproducible builds, SBOM/license review, signing, updates and recovery |
| Hardware acceptance | Boot and interface tests on the intended board revision and peripherals |

This is a porting checklist, not a completed port. No `MACHINE=mo62a` command is provided because a matching verified machine definition was not found. Do not flash an evaluation-board image to a production card as a compatibility test.

For the currently documented source workflow, use [Build from source](./build-from-source.mdx), which assembles the Debian base archive with Mo62A boot files, modules and overlays. If you need Yocto for production, request the supported layer/machine package and its validation record from InHand before choosing a build plan.
