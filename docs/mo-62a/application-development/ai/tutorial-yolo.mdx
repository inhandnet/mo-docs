The verified deployment route uses the TI YOLOX-Lite models already compiled into the image. This is different from exporting an arbitrary Ultralytics model and quantizing it for AM62A.

:::info[Scope]
Video-file deployment, inference offload and the displayed detections below were tested on Mo62A. A fresh custom-YOLO export-to-quantization-to-deployment tutorial has not passed validation, so no such result is claimed here.
:::

## Choose the verified model

| Model | Input | Use in these examples |
|---|---|---|
| YOLOX-nano-lite, 8200 | 416 × 416 | Shorter inference-call latency; useful as a runtime baseline |
| YOLOX-S-Lite, 8220 | 640 × 640 | The road, people and pet demonstrations |

List installed models:

```bash
edgeai-demo list
```

Both model directories include the original network, compiled artifacts and `param.yaml`. Keep those files together. Neither the shared name “YOLO” nor a similar input resolution makes another network compatible with these artifacts.

## Deploy the supplied video example

Follow the tested [sample-video setup](../../getting-started/first-npu-demo.mdx#run-the-sample-video-no-camera-required) to download the input, launcher and configuration. It documents the test environment's decoder changes and the display requirements.

After setup on the board:

```bash
sudo bash /tmp/mo-npu-video/run-video-demo.sh cpp
```

The configuration selects the 8220 directory and a visualization threshold of 0.4. HDMI shows boxes and class labels; the SSH terminal controls the application, not the video display. Stop the process with **Ctrl+C** before starting another pipeline.

## Quantize a custom YOLO model

Follow the acceptance stages in [Compile your own model](./compile-your-own-model.mdx). Before attempting conversion, record the exact architecture, weights, exporter version, input shape, opset, preprocessing and output decoder.

| Stage | Required evidence |
|---|---|
| CPU export check | Correct outputs from the exported ONNX graph using the intended preprocessing |
| Operator review | AM62A support for this exact graph, not support inferred from another SoC |
| Calibration | Representative inputs, the required frame count and a complete compiler log |
| Detection metadata | Head description and postprocessing compatible with this export |
| Target inference | Successful board loading, expected offload and finite, meaningful outputs |
| Accuracy evaluation | Task metrics on held-out labeled data before and after quantization |

TI's YOLOX-Lite networks are not interchangeable with standard YOLOv8/YOLO11 exports. Replacing an activation or another operator to make compilation proceed changes the network; it must be assessed against the trained model and accuracy requirements. Do not relabel a pre-compiled TI demonstration as a successful custom-model conversion.

Until this complete path is validated for a specific model revision, use the supplied models for integration work and retain custom export/quantization as an explicitly unverified step.
