## Select a compatible combination

| Component | Reference for this audit | Boundary |
|---|---|---|
| Target SoC | AM62A | Not AM62x or another accelerator |
| Host TIDL tools | `11_02_17_00` | Pin the tag and record its commit |
| TI base SDK compatibility | AM62A Linux SDK 11.01.07.05 | Patch requires corresponding target updates |
| Runtime versions listed by the tag | ONNX Runtime 1.23.0, TFLite 2.12.0, TVM 0.18.0 | Not all paths were tested on Mo62A |
| Mo62A test installation | V1.1.0 development environment | Debian integration, not an unmodified TI SDK image |

Read the [TI compatibility table](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/sdk_version_compatibility_table.md) with the [target setup notes](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/scripts/setup/README.md). Do not run TI's target updater blindly on Mo OS: it replaces firmware, libraries and runtime components. Preserve the image's tested integration.

## Prepare an isolated x86 environment

The pinned setup script requires Python 3.10; TI's CPU Docker recipe uses Ubuntu 22.04. Use a dedicated virtual environment or review the [Docker instructions](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/scripts/docker/README.md). Docker setup can install system packages and change group membership.

With Python 3.10 and its `venv` support available on the host:

```bash
sudo apt-get install libyaml-cpp-dev libglib2.0-dev python3.10-venv
git clone --branch 11_02_17_00 --depth 1 \
  https://github.com/TexasInstruments/edgeai-tidl-tools.git
cd edgeai-tidl-tools
python3.10 -m venv .venv
source .venv/bin/activate
export SOC=AM62A
./scripts/setup/setup.sh
source ./scripts/setup/setup_env.sh AM62A
git rev-parse HEAD
python3 --version
python3 -c "import onnxruntime as o; print(o.__version__); print(o.get_available_providers())"
```

Set `SOC` before setup to avoid downloading tools for every supported SoC. Setup downloads executable tools, runtime packages and example data; review its changes and allow storage for the selected components. CPU tools do not require a GPU. Repository, downloaded binary and model licenses are separate. See the [setup script](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/scripts/setup/setup.sh) and [usage guide](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/scripts/setup/README.md).

In each new shell, activate the environment and source `setup_env.sh AM62A`. A generic PyPI `onnxruntime` wheel does not include TI's providers.

## Exercise one upstream reference model

From the tool repository:

```bash
cd runtimes/examples/python/basic_example
python3 basic_example.py --config ./config.yaml \
  --models cl-ort-resnet18-v1 --compile
python3 basic_example.py --config ./config.yaml \
  --models cl-ort-resnet18-v1 --infer
```

These are upstream reference commands, not the procedure or successful outcome of the failed local experiment. Review compilation before host inference; host emulation is still not a board test. The [basic example](https://github.com/TexasInstruments/edgeai-tidl-tools/tree/11_02_17_00/runtimes/examples/python/basic_example) places artifacts under `runtimes/examples/model-artifacts/`. Selecting only `-r onnxrt` runs multiple configured ONNX models, not one smoke test.

Compilation analyzes the graph, quantizes/calibrates where required, and prepares accelerator execution and memory layout. Preserve the original or deliberately optimized model, network and I/O binaries, runtime metadata, preprocessing and postprocessing parameters. Filenames depend on the runtime and graph. See [TI's compilation documentation](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/model_compilation.md).

Exit status zero, a success banner, an artifact directory or full offload is not sufficient proof of success. Inspect the entire log, check host outputs against a reference, then validate on the target.

## Calibration and precision

Use representative inputs processed as production inputs. All-zero tensors can test timing, not calibration accuracy. Compare outputs and task metrics on held-out data.

In this tag, `basic_example.py` adjusts `advanced_options:calibration_frames` to its selected frame count; its example YAML starts with two frames. It still checks available inputs and can reject insufficient input sets. Do not generalize a direct-API failure into “fewer than 20 images always exits successfully without artifacts.” Check the [example code](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/runtimes/examples/python/basic_example/basic_example.py) and effective settings.

8-bit, 16-bit and mixed precision have different support, accuracy and performance tradeoffs. Consult the [quantization guide](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/quantization.md) and [operator evidence](./known-issues.mdx). Do not copy mixed-precision layer names or detection metadata from a different graph.

## Application builds and upgrades

The on-board C/C++ SDK can build an application around a supplied model without the x86 model compiler. See [Inference APIs](./inference-apis.mdx).

Record host tools, target firmware, libraries, runtimes and model checksums as a set. Recompile where compatibility guidance requires it and rerun accuracy and stability checks. SDK 9.2 artifacts requiring recompilation for SDK 10.0 is a [documented AM62A case](https://e2e.ti.com/support/processors-group/processors/f/processors-forum/1407278/sk-am62a-lp-model-maker-sdk-9-2-and-10-compatible), not evidence that all patch updates are incompatible.
