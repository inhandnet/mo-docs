This is step 1 of the warehouse zone-occupancy example: install the x86 tools here, [compile a new model bundle](./compile-your-own-model.mdx), then [deploy the business application](./tutorial-yolo.mdx). No GPU, activation replacement or retraining is needed for the model's existing `person` class.

TI's official repository is [TexasInstruments/edgeai-tidl-tools](https://github.com/TexasInstruments/edgeai-tidl-tools), with a plural `tools`. The [AM62A model guide](https://software-dl.ti.com/processor-sdk-linux/esd/AM62AX/11_01_07_05/exports/docs/edgeai/inference_models.html#import-custom-models) places model compilation on an x86 host. The board runs the result; ordinary C/C++ application compilation on Mo62A is a different task.

## Select a compatible combination

:::warning[One tested compatibility baseline]
Treat the x86 compiler, graph, compiled artifacts, target runtime/provider libraries and C7x firmware as one deployment set. Updating one component alone can cause loading or inference failures. Matching only the ONNX Runtime version string is insufficient: the generic PyPI wheel does not contain TI's provider.

Alignment means a tested combination, not an identical number on every component. Do not replace the board's Python or NumPy with the host versions.
:::

| Component | Pinned baseline | Location |
|---|---|---|
| TI source | `11_02_17_00`, commit `d2be7203e5680298d7f54bcbd38e299d1bc22bfd` | x86 host |
| AM62A compiler | `REL.TIDL.11.02.17.00`, commit `6f5289fd1c17cf03ff21caa842c9706a06e11fcc` | x86 host |
| Host Python / runtime | Python 3.10; TI ONNX Runtime 1.23.0 | Isolated virtual environment |
| Host data libraries | NumPy 1.23.0, ONNX 1.14.0, OpenCV 4.10.0.84 wheel | Isolated virtual environment |
| Target | V1.1.0 development installation; Python 3.13.5, TI ONNX Runtime 1.23.0, NumPy 2.2.4, OpenCV 4.10.0 | Mo62A |
| Target firmware / libraries | Selected C7x firmware and five runtime libraries matched TI's `11_02_17_00` archives | Mo62A |

The [measured version map](../../resource-download/version-map.mdx) records the inventory and binary comparisons. It is not a pristine release-image manifest. TFLite 2.12.1, TVM 0.18.0 and DLR 1.13.0 are also installed on that board, but are not used by this ONNX example; their presence does not validate those paths.

The [TI compatibility table](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/sdk_version_compatibility_table.md) associates this patch with AM62A SDK 11.01.07.05 and corresponding target updates. Do not run TI's target updater blindly on Mo OS: it replaces libraries and firmware. Preserve the tested integration.

## Prepare an isolated x86 environment

TI's CPU Docker recipe uses Ubuntu 22.04 and Python 3.10. This walkthrough was exercised on x86 Ubuntu 24.04.4 with a separately installed Python 3.10.20. That observation is not a claim that TI supports every OS combination. Consult the [TI Docker instructions](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/scripts/docker/README.md) for its reference environment.

Provide Python 3.10 with `venv`, Git, curl, tar, a C++ runtime and TI's required host libraries (`libyaml-cpp` and GLib). On Ubuntu 22.04 an administrator can install prerequisites with:

```bash
sudo apt-get update
sudo apt-get install git curl tar libyaml-cpp-dev libglib2.0-dev python3.10-venv
```

Ubuntu 24.04's default Python is not 3.10. Do not replace its system interpreter or assume the command above provides 3.10 there: provision it separately or use the reference container. If a managed Python omits `ensurepip`, its existing pip must support `--python` to bootstrap only the new virtual environment.

Download <a href={useBaseUrl('/downloads/ai/mo62a-zone-demo.tar.gz')} download>the complete source/input archive</a> and <a href={useBaseUrl('/downloads/ai/mo62a-zone-demo.tar.gz.sha256')} download>its checksum</a> into one directory on the x86 host. It includes scripts, two prepared CC BY 4.0 clips, configuration, tests and attribution. It contains no TI tools or model weights.

```bash
sha256sum -c mo62a-zone-demo.tar.gz.sha256
tar -xzf mo62a-zone-demo.tar.gz
cd zone-demo
bash setup_host.sh ./host
source ./activate_host.sh ./host
python -m pip check
```

Use a new directory. Setup refuses to replace an existing `host`. It clones the official source and checks its commit, creates a virtual environment, installs the pinned TI wheel and dependencies, and downloads/checks the AM62A tool archive. It does not use sudo, modify global pip or access the board. Review <a href={useBaseUrl('/downloads/ai/zone-demo/setup_host.sh')}>setup_host.sh</a> and <a href={useBaseUrl('/downloads/ai/zone-demo/requirements-host.txt')}>requirements-host.txt</a> before running downloaded code.

## Reactivate and verify the environment

In every new x86 shell, enter the extracted `zone-demo` directory:

```bash
source ./activate_host.sh ./host
git -C host/edgeai-tidl-tools rev-parse HEAD
cat host/tidl_tools/version.txt
python --version
python -c "import onnxruntime as o; print(o.__file__); print(o.__version__); print(o.get_available_providers())"
```

The compiler must report `BRANCH=REL.TIDL.11.02.17.00` and the binary commit above. Activation sets `SOC=AM62A`, `TIDL_TOOLS_PATH` and the tool library search path. Do not install generic `onnxruntime` into this environment or install host requirements on the board.

The floating-point reference can use `--backend cpu` in this same TI environment: the application explicitly selects `CPUExecutionProvider`. Training/export packages for other models belong in a separate environment.

## Track upstream without changing the deployment baseline

These commands inspect official upstream state without switching the checked-out source or installing packages:

```bash
git -C host/edgeai-tidl-tools remote get-url origin
git -C host/edgeai-tidl-tools fetch origin
git -C host/edgeai-tidl-tools ls-remote --tags origin
git -C host/edgeai-tidl-tools describe --tags --exact-match HEAD
```

The origin should be `https://github.com/TexasInstruments/edgeai-tidl-tools.git`. Keep the tag fixed for this tutorial. Do not routinely run `git pull` and setup in a working environment. Evaluate a new release separately against its AM62A compatibility table, required target updates and regressions.

## Calibration and precision

The example uses 32 frames from a separate clip and three calibration iterations, with 8-bit base quantization and TI's selected 16-bit outputs. It is mixed precision, not an all-8-bit claim. The source architecture and activations are unchanged. Neither 32 frames nor full offload establishes production accuracy.

See the [quantization guide](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/quantization.md), [compilation options](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/model_compilation.md) and [AM62A operator evidence](./known-issues.mdx). Do not copy tensor names or head metadata to a different graph.

## Application builds and upgrades

The on-board SDK can build C/C++ applications around an already compiled model; see [Inference APIs](./inference-apis.mdx). For an intentional AI-stack update:

1. Save the known-good model and image/configuration. Record compiler identities, runtime imports, resolved libraries and C7x firmware hashes.
2. Review AM62A compatibility and integrate target changes as a set. Replacing one library or wheel is not a complete update.
3. Build a separate host environment and recompile where required. Never mix a new graph with an old artifact directory.
4. Validate the original baseline, CPU reference, host simulation, target outputs, task accuracy and sustained application behavior before adopting the new set.

Version skew is one possible cause of failure, not a diagnosis established by an error message alone. Incorrect inputs, unsupported graphs and incomplete artifacts need separate checks. TI's [SDK 9.2 to 10.0 E2E case](https://e2e.ti.com/support/processors-group/processors/f/processors-forum/1407278/sk-am62a-lp-model-maker-sdk-9-2-and-10-compatible) documents one recompilation requirement, not a rule about every patch.
