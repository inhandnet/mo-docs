The Mo62A installation includes compiled bundles derived from TI model-zoo entries. Use them as a starting point for the [demo launcher](../../getting-started/first-npu-demo.mdx) and [inference APIs](./inference-apis.mdx), checking each application's task and runtime support.

:::info[Tested software]
The inventory is from the V1.1.0 development installation with TIDL `11_02_17_00`. Installation, successful inference, accuracy and video integration are separate checks. Only the two models with downloadable raw timing records are assigned audited latency figures here.
:::

## Auditable timing results

The [benchmark page](./benchmarks.mdx) provides the script and 100 samples per model after five warm-up calls: nano mean 10.900 ms, small mean 40.402 ms. Both reported 329/329 offloaded nodes. These are synchronous inference-call timings with blank input, not accuracy or end-to-end video FPS.

## Run a model

Pick a model by name or number with the demo launcher, which builds the camera or video pipeline for it:

```bash
edgeai-demo list
sudo edgeai-demo run ONR-OD-8200-yolox-nano-lite-mmdet-coco-416x416 --backend cpp --camera csi
```

For your own program, pass the model directory to the [Python or C/C++ API](./inference-apis.mdx). Each directory contains:

| File | Content |
|---|---|
| `param.yaml` | Task type, input resolution, pre-processing (mean, scale, layout) and post-processing parameters used by the demo applications |
| `model/` | The ONNX or TFLite network, plus `.prototxt` meta files for detection models |
| `artifacts/` | Compiled network/I/O binaries and runtime-specific partition metadata |
| `config.yaml` | Recorded configuration where supplied; verify provenance and effective options before reuse |
| `dataset.yaml` | Application class/label mapping where required |


## Models that are not included

`/opt/model_zoo/unsupported_models.txt` records specific excluded entries, including shape problems, high latency and a local importer failure. It does not establish architecture-wide restrictions. An ONNX segmentation entry is not necessarily an accuracy-equivalent replacement for a TFLite entry. See [Known issues](./known-issues.mdx).

## Add more models

For a complete tested example, follow [Set up the toolchain](./toolchain.mdx), [Compile your own model](./compile-your-own-model.mdx) and [the warehouse application](./tutorial-yolo.mdx). They download TI YOLOX-tiny-lite 8210, which is not in the inventory above, and create new artifacts from separate calibration footage. The standalone project uses explicit code/configuration and `bundle.json`; it is not automatically a drop-in `edgeai-demo` entry with `param.yaml`.

The [TI AM62A model guide](https://software-dl.ti.com/processor-sdk-linux/esd/AM62AX/11_01_07_05/exports/docs/edgeai/inference_models.html) links to [TI's model zoo](https://github.com/TexasInstruments/edgeai-tensorlab/tree/main/edgeai-modelzoo). Select an AM62A bundle compatible with the target stack and runtime, preserve licenses and metadata, then validate the application. Matching one version string is insufficient. Use a new directory and retain the known-good baseline; see [Compile your own model](./compile-your-own-model.mdx).
