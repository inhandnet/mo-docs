Mo OS ships a set of models from the TI model zoo, already compiled for the C7x accelerator and the TIDL version of the image. They are ready to run with the [demo launcher](../../getting-started/first-npu-demo.mdx), the [inference APIs](./inference-apis.mdx) or your own application, and they are the reference for how a compiled model directory looks.

:::info[Tested software]
This page lists the models in **Mo62A image V1.1.0** (built 2026-08-19), compiled for TIDL 11_02_17_00. Inference times were measured on the test board with ONNX Runtime 1.23.0, ten runs of a blank input after one warm-up run; they are indicative, not guaranteed, and exclude pre- and post-processing.
:::

## Models in the image

The models live in `/opt/model_zoo/`, one directory per model, and `edgeai-demo list` shows them grouped by task. Every ONNX model below ran with all of its layers on the accelerator (one subgraph, 100 % of nodes offloaded).

| Task | Input | Inference | Model directory |
|---|---|---|---|
| Classification (ImageNet) | 224×224 `uint8` | 7.9 ms | `ONR-CL-6360-regNetx-200mf` |
| Classification (ImageNet) | 224×224, TFLite | — | `TFL-CL-0000-mobileNetV1-mlperf` |
| Object detection (COCO) | 416×416 `uint8` | 10.5 ms | `ONR-OD-8200-yolox-nano-lite-mmdet-coco-416x416` |
| Object detection (COCO) | 512×512 `uint8` | 23.9 ms | `ONR-OD-8020-ssd-lite-mobv2-mmdet-coco-512x512` |
| Object detection (COCO) | 640×640 `uint8` | 39.7 ms | `ONR-OD-8220-yolox-s-lite-mmdet-coco-640x640` |
| Face detection (WIDER FACE) | 640×640 `uint8` | 41.5 ms | `ONR-OD-8420-yolox-s-lite-mmdet-widerface-640x640` |
| Object detection (COCO) | 320×320, TFLite | — | `TFL-OD-2020-ssdLite-mobDet-DSP-coco-320x320` |
| Human pose (keypoints) | 640×640 `float32` | 55.4 ms | `ONR-KD-7060-human-pose-yolox-s-640x640` |

The directory name encodes the runtime (`ONR` = ONNX Runtime, `TFL` = TFLite), the task (`CL`, `OD`, `KD`, `SS`) and the TI model zoo number. TFLite models run through the TIDL delegate and were not included in the ONNX Runtime measurement.

## Run a model

Pick a model by name or number with the demo launcher, which builds the camera or video pipeline for it:

```bash
edgeai-demo list
sudo edgeai-demo run ONR-OD-8200-yolox-nano-lite-mmdet-coco-416x416 --backend cpp --camera csi
```

For your own program, pass the model directory to the [Python or C/C++ API](./inference-apis.mdx). Each directory contains:

| File | Content |
|---|---|
| `param.yaml` | Task type, input resolution, pre-processing (mean, scale, layout) and post-processing parameters used by the demo applications |
| `model/` | The ONNX or TFLite network, plus `.prototxt` meta files for detection models |
| `artifacts/` | TIDL compilation output for this TIDL version; `allowedNode.txt` lists the layers that run on the accelerator |
| `config.yaml` | The toolchain options TI used to compile the model; reuse them when you recompile |
| `dataset.yaml` | Class names of the training dataset |


## Models that are not included

`/opt/model_zoo/unsupported_models.txt` lists TI model zoo entries that do not compile or run on this TIDL version and were therefore left out, with the reason for each: odd input resolutions, high latency, and one TFLite segmentation model whose import crashes in TIDL 11_02_17_00. The ONNX `deeplabv3lite` models cover the same use case.

## Add more models

Any model from the [TI edgeai-modelzoo](https://github.com/TexasInstruments/edgeai-modelzoo) with the same TIDL version can be added by copying its compiled directory into `/opt/model_zoo/`. Models compiled for other TIDL versions fail at load time and must be recompiled; see [Set up the toolchain](./toolchain.mdx) and [Known issues](./known-issues.mdx). The planned Mo model hub will publish additional pre-compiled models for each image version.
