## Read the operator reports carefully

The tag's [8-bit report](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/test/reports/Operator_Test_Report_AM62A_8bits.xlsx) and [16-bit report](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/test/reports/Operator_Test_Report_AM62A_16bits.xlsx) identify AM62A, SDK 11.01.07.05 and TIDL tools/firmware `REL.TIDL.11.02.17.00` on their `Versions` sheets. Selected `Summary` results:

| Operator cases | 8-bit target pass / total | 16-bit target pass / total |
|---|---|---|
| Relu; HardSwish (each) | 22 / 22 | 22 / 22 |
| Sigmoid | 0 / 22 | 22 / 22 |
| LeakyRelu | 0 / 32 | 32 / 32 |
| Acos, Asin, Asinh, Exp, Log, Mish (each) | 0 / 22 | 22 / 22 |
| Tan | 0 / 22 | 8 / 22 |

These are test-case counts, not permanent operator-wide verdicts:

- `Tan` does not pass all 16-bit cases.
- 8-bit `Sigmoid` also has 0/22 host passes, not “correct on the PC, fails only on the board.”
- `TargetPass` does not alone prove acceleration: 16-bit `ConvTranspose` has 2116 target passes but zero TIDL offloads.

Open `Versions` first, then compare `TIDL Offload`, `Host Inference` and `Target Inference` on the individual operator sheet. Each case records input shapes, data types and attributes. `Failed` does not, by itself, distinguish a graph-creation failure from an output-accuracy failure: the [test framework](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/test/tidl_unit/README.md#evaluation-metrics) also compares numerical outputs against reference outputs. Preserve the corresponding run log before assigning a cause.

Use reports for the selected release, not a different tag's results. A newer tag can temporarily lack reports; for example, the [`11_02_21_00` report README](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_21_00/test/reports/README.md) explicitly says its reports are not yet available. This is not evidence that a failed case has been fixed, and does not change this page's pinned baseline.

The same tag's [operator table](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/operators.md) lists Sigmoid and LeakyRelu subject to constraints. It explicitly excludes 16-bit deconvolution on AM62A. Check graph attributes, precision, offload and accuracy when a support entry and a test result appear to disagree.

## 16-bit and YOLO conclusions

AM62A is not categorically limited to 8-bit inference. TI confirms up to 16-bit quantization in [this E2E answer](https://e2e.ti.com/support/processors-group/processors/f/processors-forum/1407278/sk-am62a-lp-model-maker-sdk-9-2-and-10-compatible). This does not guarantee every 16-bit graph works or constitute a new Mo62A 16-bit validation.

Do not infer that every YOLOv8/YOLO11 graph must fail from one operator report. TI's [AM62A YOLO discussion](https://e2e.ti.com/support/processors-group/processors/f/processors-forum/1443278/sk-am62a-lp-how-to-run-yolov8-v11-in-this-board) covers version-specific configurations, architecture changes, retraining and detection-head metadata. It is not blanket certification for arbitrary exports. The [local YOLO page](./tutorial-yolo.mdx) validates one newly compiled TI YOLOX-tiny-lite 8210 model and an illustrative warehouse application, not arbitrary upstream exports.

### Validate the whole model

An operator test does not validate a complete detector. Check the actual exported graph, compiler fusion, input shapes, precision, target execution and task accuracy. Selecting a 16-bit output can also change adjacent layers' precision; inspect the compiled graph and measured resource use.

Changing an activation function is not a lossless conversion. Prefer a model with matching architecture and trained weights. An architecture change requires training-framework changes and accuracy evaluation before export and compilation; editing generated TIDL binaries is not a training workflow.

|---|---|---|

| Host success banner | One stage reported success | Correct target outputs, accuracy or stability |
| New YOLOX-tiny-lite 8210 recipe | 32-frame calibration, raw host/target agreement and three complete video runs | Labeled accuracy, arbitrary-model support or long-duration qualification |

## Inspect the excluded-model record

```bash
cat /opt/model_zoo/unsupported_models.txt
```

The installed file records individual TFLite/TVM exclusions, a high-latency segmentation model and an importer failure. Some reasons concern performance, not inability to execute. It is an image-maintenance record, not TI's universal compatibility list.

## Diagnose errors in context

Preserve the compiler/application logs, model/artifact checksums, version manifest and target log. If installed, the remote-log utility provides firmware messages:

```bash
sudo /opt/vision_apps/vx_app_arm_remote_log.out
```

Stop viewing with Ctrl+C. See [TI's debugging guide](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/debugging.md) for model, layer and runtime diagnostics.

| Symptom | Checks, not a unique diagnosis |
|---|---|
| `Create state function failed`, `algInit failed` | Preceding target errors, compatible versions, model integrity, operator constraints, runtime memory and concurrent users |
| `algAlloc failed` | Allocation diagnostics and resource use; not automatically an unsupported operator |
| Missing symbol / `Could not load function` | Loaded library paths and ABI compatibility; retain the exact symbol/error |
| `user_data_object` type error | Object type expectations and integrated TIOVX/TIDL libraries |
| Permission denied | Named device/file and service identity; use appropriate access controls, not world-writable devices |
| Numeric return code such as `-16` | API and accompanying log; this does not uniquely mean “not root” |
| Unexpected tensor type/shape | Actual tensors, metadata and TI wrapper's I/O requirements |
| Detection metadata/prototext error | Path, format, graph/head correspondence and compiler options |
| Lower FPS or stalled pipeline | Caps, queueing, resource sharing and logs; no single scaler or signal-related cause is implied |

TI's [AM62A dataflows](https://software-dl.ti.com/processor-sdk-linux/esd/AM62AX/11_01_07_05/exports/docs/edgeai/edgeai_dataflows.html) include multiple scaler elements. “Two scaler elements always conflict” is not a valid general rule.

## Runtime settings and recovery

The pinned [ONNX wrapper](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/runtimes/tidl_wrapper/python/onnxrt/onnxrt_wrapper.py) sets TI-specific I/O validation options for ONNX Runtime 1.23.0. Follow the [Python example](./inference-apis.mdx), including explicit tensor checks. These options are not a general fix for unrelated errors.

Keep graph optimization consistent with artifacts. CPU fallback needs a CPU implementation; lower offload is not itself failed inference.

Stop applications gracefully to release resources. If an experiment stalls, preserve diagnostics, stop that experiment and check a known-good model. Do not reset remote processors or replace firmware as a generic fix: the shared resources may serve other applications.

In a separate [AM62A SDK 9.2 E2E case](https://e2e.ti.com/support/processors-group/processors/f/processors-forum/1451931/processor-sdk-am62a-using-the-am62a-chip-development-board-for-ai-model-development-i-encountered-a-runtime-issue-and-seek-assistance), TI explains that incomplete shutdown can leave remote resources allocated and recommends explicit cleanup in signal handling. Ctrl+C is not a guarantee of cleanup in an arbitrary program. That older case supports checking resource state; it does not establish the cause of our local ResNet18 failure.
