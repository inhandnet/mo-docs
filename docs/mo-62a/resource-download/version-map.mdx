Use this page as the version reference for Mo62A AI tutorials. The model compiler, board Python environment, runtime libraries and firmware have separate identities; they do not all share one version number.

:::warning[Do not assemble the stack from unrelated releases]
The complete deployment must use one tested compatibility baseline: x86 TIDL tools and runtime, model graph/artifacts, target runtime/provider libraries, C7x firmware and the application/vision integration. A partial update can break inference even when each package imports successfully. Keep a manifest for the whole set, not only a list of top-level Python versions. See the [upstream tracking policy](../application-development/ai/toolchain.mdx#track-upstream-without-changing-the-deployment-baseline) and [controlled upgrade sequence](../application-development/ai/toolchain.mdx#application-builds-and-upgrades).
:::

:::info[What was inspected]
The read-only audit on 2026-10-21 inspected the current V1.1.0 development installation. It did not reflash the board, install packages, run TI's target updater or restart a remote processor. This board has development changes, including the video-decoder fixes described in [the first NPU demo](../getting-started/first-npu-demo.mdx#run-the-sample-video-no-camera-required). This inventory is not a pristine V1.1.0 release-image manifest or a compatibility guarantee for every later image.
:::

## Host tools are a separate environment

| Item | Pinned host/reference value | Relationship to Mo62A |
|---|---|---|
| TI base compatibility | AM62A SDK 11.01.07.05 | Compatibility baseline, not a claim that Mo OS is the unmodified SDK image |
| Model compiler repository | `edgeai-tidl-tools` tag `11_02_17_00` | Pin the repository commit recorded below |
| Compiler binary release | `11.02.17.00` | AM62A CPU tools; `version.txt` reports `REL.TIDL.11.02.17.00` and its own binary-source commit |
| x86 setup Python | 3.10 | The pinned setup script's host requirement; do not replace board Python 3.13.5 |
| TI reference runtimes | ONNX Runtime 1.23.0, TFLite 2.12.0, TVM 0.18.0 | These are not a verbatim inventory of the Debian board packages |

The inspected compiler repository commit is:

```text
d2be7203e5680298d7f54bcbd38e299d1bc22bfd
```

Its upstream is the official [TI repository](https://github.com/TexasInstruments/edgeai-tidl-tools). This is a pinned snapshot, not a floating "latest" requirement. For the measured ONNX path, the combination is TIDL `11_02_17_00`, TI ONNX Runtime 1.23.0 and the AM62A `edgeai/11_1` target firmware/libraries from that same TIDL release. The `11_1` SDK compatibility directory and Vision Apps filename `11.1.0` do not indicate an accidental mismatch with TIDL `11.02.17.00`. Verify archive provenance and hashes rather than renaming or replacing components to make their numbers look equal.

TI's [pinned compatibility table](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/docs/sdk_version_compatibility_table.md) lists `11_02_17_00` as a backward-compatible patch for AM62A SDK 11.01.07.05. The [target setup script](https://github.com/TexasInstruments/edgeai-tidl-tools/blob/11_02_17_00/scripts/setup/update_target.sh) selects AM62A `edgeai/11_1` firmware/libraries and reference OSRT packages. Its Python wheels and NumPy installation steps are not instructions to overwrite this Debian/Python 3.13 integration.

The TFLite 2.12.0 versus 2.12.1 difference is real. Neither matching major/minor numbers nor a successful import proves delegate ABI compatibility or model correctness. Validate a specific TFLite model before claiming that path works. The same installation-versus-inference distinction applies to TVM and DLR. The published [ONNX Python/C++ smoke tests](../application-development/ai/inference-apis.mdx) validate only their stated models and paths.

## Repeat the checks on your board

Run these read-only inventory commands on Mo62A, not in the x86 compiler environment:

```bash
mo-version
uname -r
python3 --version
python3 - <<'PY'
import importlib
import importlib.util
for name in ('onnxruntime', 'tflite_runtime', 'tvm', 'dlr', 'cv2', 'numpy'):
    try:
        module = importlib.import_module(name)
        print(name, getattr(module, '__version__', 'unreported'), module.__file__)
    except Exception as error:
        print(name, type(error).__name__, str(error))
print('tidlruntime installed:', importlib.util.find_spec('tidlruntime') is not None)
import onnxruntime as ort
print('providers:', ort.get_available_providers())
PY
gst-launch-1.0 --version
gst-inspect-1.0 tiovx
gst-inspect-1.0 ti
readlink -f /lib/firmware/am62a-c71_0-fw
sha256sum /lib/firmware/am62a-c71_0-fw
ldd /usr/local/bin/app_edgeai
```

Check the imported module's path as well as its version: a virtual environment or user-installed wheel can shadow the system package. Missing Python distribution metadata alone does not prove a vendor-installed module is absent. Conversely, seeing `TIDLExecutionProvider` is not proof that a particular graph is fully offloaded.

Keep the exact source revision, image hash, target-library/firmware hashes, model bundle and application configuration with deployment records. Do not upgrade or downgrade the board merely to make version strings equal. For a deliberate stack change, use [Set up the toolchain](../application-development/ai/toolchain.mdx) and repeat correctness, accuracy, stability and [performance checks](../application-development/ai/benchmarks.mdx).
