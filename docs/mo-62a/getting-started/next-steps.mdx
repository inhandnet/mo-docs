## Move from the demo to your own AI application

The [first NPU demo](./first-npu-demo.mdx) explains how to run and interpret an existing application. Model conversion, inference APIs and application design belong in [AI development](../application-development/ai/index.mdx).

For a concrete starting point, the image's C/C++ SDK provides examples in `/usr/share/edgeai-cpp-examples/` and an accompanying `DEV_GUIDE.md`. The maintained [SDK example guide in mo-examples](https://github.com/inhandnet/mo-examples/blob/master/products/mo62a/ai/edgeai-cpp/DEV_GUIDE.md) is currently in Chinese:

- `hello_inference` loads a compiled model, runs one inference with zero-filled input and prints the outputs. It checks the inference environment without a camera or display; it is not a real-scene accuracy test.
- `app_edgeai` provides the camera/video → inference → HDMI application and accepts YAML configurations. Use it as a starting point for a complete pipeline.

Check the [version map](../resource-download/version-map.mdx) before replacing the runtime or compiling a model. A model file alone is not a substitute for compatible TIDL artifacts. Use the inference API, model compilation and benchmark guides for each documented path. The installed example copy is part of the BSP image integration; mo-examples maintains the application-side source.

The older source SDK guide mentions ONNX Runtime 1.15; the current board's Python and C/C++ runtimes both report 1.23.0. Use [Inference APIs](../application-development/ai/inference-apis.mdx) and the measured version map for the current runtime baseline, not that older version comment.

When evaluating a change, keep the input, model and resolution fixed. Record the backend and decoder, allow warm-up and compare throughput with CPU load and accelerator activity. The demo's [C/C++ versus Python comparison](./first-npu-demo.mdx#cc-and-python-same-model-same-video) shows one measured example; it is not a performance guarantee for other workloads.

## Keep a reproducible setup

Record the OS image version, board revision, camera or input video, model directory and application configuration that worked. Save your configuration files and application changes before reinstalling the OS; flashing a new image erases the selected storage device.

For system configuration, continue to [Mo OS](../mo-os/index.mdx). For an image update, use [Install the OS](./install-os.mdx) and read the release notes before flashing.
